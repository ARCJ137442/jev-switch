## 一、核心概念：可调用端点（Invoke Endpoint）

**路由表中的一个端点 = 一个「API 地址固定、模型固定、API token 固定」的可调用端点。**

三元组即身份：

```text
endpoint ≡ ( API 地址 base_url , 模型 model , API token api_key )
```

由此推导三层概念的分工：

| 概念 | 固定什么 | 可变什么 | 说明 |
|---|---|---|---|
| **提供商 Provider** | `base_url` + `api_key`（归属主体） | — | **一个地址 = 一个提供商**（用户裁定） |
| **模型 Model** | 提供商内的标识 | 提供商可挂 N 个 | 同一地址下多模型 = **同提供商多端点**，绝不拆成多个提供商 |
| **可调用端点 Endpoint** | `base_url` + `model` + `api_key` 三者全固定 | 不可变 | **路由边真正指向的东西** |

即：**路由的右侧不是「提供商」，而是「端点」**；提供商只是端点的分组容器（地址与 token 的归属）。

### 两类端点（按「模型维度」是否钉死）

| 类型 | 判定 | 模型维度 | 例子（本仓库配置） |
|---|---|---|---|
| **钉死端点** | `[[routes]].upstream_model` 显式设置；或旧式 `[router]` **同名透传**（公共 id = 上游 id，收发同名） | **固定** ✅ 三元组全固定 = 严格意义的可调用端点 | `jev-zh` → (18765, `laya-multilingual`, laya-key)；`laya-english` 同名透传 → (18765, `laya-english`, …) |
| **透传端点** | 无 `upstream_model` | **= 调用方入参 model**（地址与 token 固定，模型浮动） | `local/*` → (18765, *调用方的* `local/qwen`, …) |

> **概念纪律**：只有三元组全固定的**钉死端点**才可被称作「可调用端点」的严格形态；透传端点是**半开放端点**（模型维度让渡给调用方），UI 必须用 badge 显式区分两者，禁止把透传端点伪装成钉死端点。

### 数据模型已表达（契约零改动）

`contracts/03` 的 `[[routes]]` = `{ left(公共 id), right(提供商 id), upstream_model(端点模型) }` + provider 段的 `base`/`api_key` → **endpoint 三元组可完整推导**。无需修改任何契约；本文只做概念澄清与 UI 演进要求。

## 二、实证案例：Laya 单提供商多模型

Laya 官方三 checkpoint（`NandhaKishorM/laya` README）+ Router，全部挂在**同一个本地地址** `127.0.0.1:18765`（一个提供商 `laya`）：

| 公开 model id（我们的） | checkpoint | 参数/上下文 | 分派方式 |
|---|---|---|---|
| `laya-english` | ModernBERT-large 英语 | 421M / 512 | 显式钉死 |
| `laya-multilingual` | mmBERT 多语言（100+ 语） | 322M / 1024 | 显式钉死 |
| `laya-router` | **Router 版**：按文种自动分派 | 双权重常驻 | 自动（非拉丁→multilingual，拉丁英语→english） |
| `laya-typed-decisions` | typed-decisions 工作流 | 421M / 1024 | 显式钉死（懒加载） |

别名兼容：`convaiinnovations/laya[-multilingual|-typed-decisions]`、`english`/`multilingual` 等 laya 官方短名。

**服务**：[`scripts/laya_multi_server.py`](../scripts/laya_multi_server.py)
- 单地址 18765，按 `model` id 分派；复用 `laya.Router`（0.3.4 内置）；
- **离线直载**本机快照 `E:/hf-cache/.../snapshots/1c5edc17…`（三权重本机全齐，零下载）；启动预载 english+multilingual 双权重（实测 **~8s 就绪**，`loaded:["english","multilingual"]`）；
- 钉死 id 走 `predict(model=key)`（显式优先，绕过检测）；`laya-router` 走脚本检测；
- 响应回传 `x_backend_model`（实际命中 checkpoint）与 `x_routing`（完整路由决策：reason/detection）；
- 推理全局锁串行（本地单机演示，避免 LRU/并发竞态）。

## 三、配置实证（`rs/providers.example.toml`）

```toml
[router]                       # 同名透传 = 钉死端点（模型=公共 id 本身）
"laya-english"    = "laya"     # (18765, laya-english,    laya-token)
"laya-multilingual" = "laya"   # (18765, laya-multilingual, laya-token)  ← 单提供商多模型
"laya-router"     = "laya"     # (18765, laya-router,     laya-token)
"typesafe-ai/jev" = "vercel"   # (ai-gateway.vercel.sh, typesafe-ai/jev, vercel-key)

[[routes]]                     # 显式钉死：公共 id → 提供商内某模型接口
left = "jev-zh"                #   收发同名不成立 → 必须 upstream_model 钉住模型
right = "laya"
upstream_model = "laya-multilingual"
```

**跨提供商的同一公共模型**（既有）：`jev` → p10 (vercel, `typesafe-ai/jev`) + p30 (laya, `laya-english`) ——
「一个公共模型怎样路由到**不同提供商的不同模型端点**」由此成立；`jev-zh` 追加演示「同一提供商内的**另一个模型端点**」。

### 当日实测（节选，UTF-8 字节体；PS5.1 `-Body` 字符串是 latin1，中文必须以 bytes 发）

| # | 调用 | 结果 |
|---|---|---|
| S1 | `laya-english` + 英文 | 200，`x_backend_model:"english"`，noul=0.9256 / 185ms |
| S2′ | `laya-multilingual` + 中文 | 200，`x_backend_model:"multilingual"` / 75ms |
| S3′ | `laya-router` + 中文（UTF-8） | 200，**`x_backend_model:"multilingual"`**，reason=`non-Latin script (han, 100% of letters); the English checkpoint cannot read it` / 79ms |
| S4 | `laya-router` + 英文 | 200，reason=`English Latin text` |
| S5 | 未知 id `nope` | 400 + available 清单 |
| S6′ | daemon `jev-zh`（经 upstream_model 改写） | 200，`x_backend_model:"multilingual"`，`upstream_calls:1` |
| S7 | daemon `jev` failover（死 vercel→laya） | 200，`upstream_calls:4`（回归无损） |
| — | daemon `GET /v1/models` | 7 模型：`jev-zh / laya-english / laya-multilingual / laya-router / local/*` → **upstream 全 laya 同卡**，`jev / typesafe-ai/jev` → vercel |
| — | `cargo test --workspace` | **142/142**（改配置后门禁复跑） |

> 注：Laya noul 数值偏低/偏怪属**已知 zero-shot 低准确率**（`06` §四实测 17.5%，MVP 明文不管准确率），与路由正确性无关；路由正确性以上表 `x_backend_model` / `x_routing` 为准。

## 四、Routing UI 表现（落盘：`design/01` §6.2 的演进方向）

**现状**（B3 二部图）：右列 = 平铺提供商节点（`rightIds = providers ∪ routes.right`，全是提供商 id，天然无「三个 laya」重复）；边 badge 显示 `p=N / sticky`；`upstream_model` 在边浮层可编辑。

**目标形态（本裁定的 UI 表达）**：

```text
  公共 model id            提供商（大卡片 = 地址+token 归属）           可调用端点（端口）
┌──────────────┐   ┌──────────────────────────────────────┐
│ jev     [•]  │──▶│ ● laya   127.0.0.1:18765            │
│              │   │   ┌────────────────────┐  ← 端口: laya-english     [钉死] │
│ jev-zh  [•]  │──▶│   ├────────────────────┤  ← 端口: laya-multilingual [钉死] │
│              │   │   ├────────────────────┤  ← 端口: laya-router       [自动] │
│ local/* [~]  │──▶│   └────────────────────┘  ←（透传端点挂卡片级: [透传]）   │
└──────────────┘   │   key sk-****cafe · mask-only                         │
                   └──────────────────────────────────────┘
                   ┌──────────────────────────────────────┐
                   │ ● vercel  ai-gateway.vercel.sh        │
                   │   └─ 端口: typesafe-ai/jev   [钉死]   │
                   └──────────────────────────────────────┘
```

1. **右列 = 提供商大卡片**（与 Providers 页 §6.1 卡片同源组件：状态点 / base / 掩码 key / Probe）；
2. **卡片内每个「钉死模型」= 一个端口（endpoint port）**：端口标签 = 模型 id（+ token 掩码尾 4、地址短形——三元组可视化）；
3. **连线锚在端口上**，不再锚在裸提供商上 —— 边的语义从「发给提供商」精确为「发给 (地址, 模型, token) 端点」；
4. **透传端点**（无 `upstream_model`，如 `local/*`）挂在**卡片级**并打 `[透传]` badge，提示模型=调用方入参；
5. **单提供商多模型的 UI 表现 = 卡片内多端口**（如 Laya 卡片 3 个端口），**不是**右列出现多个同名提供商节点；
6. **数据流不变**：拖端口 ↔ `[[routes]]{right, upstream_model}`；`PUT /v1/admin/routes` 整表语义、检环、键盘表单等价路径全部保持 —— 这是 `contracts/03` §6 实践条款内的视图升级，**契约零改动**。

## 五、边界与留置

| 项 | 处置 |
|---|---|
| 同地址不同 token 的多端点（如共享网关多账号） | **现阶段不支持**：token 属提供商层，同地址端点共享；若未来需要 → 届时以「endpoint 层 token 覆写」走契约修订案，不擅改 contracts/04 |
| `laya-typed-decisions` 端点 | 服务已可显式调用（懒加载），example 配置暂不列（YAGNI，需要时加一行 `[router]`） |
| PS5.1 `Invoke-WebRequest -Body` 中文编码 | 必须 `UTF8.GetBytes` 字节体 + `charset=utf-8`，否则 latin1 拧成 `?`（本次实测踩过并已修正所有中文用例） |
| Laya noul 准确率 | 已知限制（06 §四），不在本文/本期范围 |
