# v0.10.2 Release Candidate Verification

**状态：**本地发布候选已通过；GitHub Release 使用 `v0.10.2` tag，并由 workflow 标记为预发布。远端 CI/Release 结果以 Actions 为准。

## 目的

本版本是 v0.10.1 之后的原子配置写入修复预览。目标是消除普通 UI、CLI 和 Agent 配置路径中的整表覆盖，并保证非法路由图、悬空 provider 分支和入口元数据/路由分裂不会在提交后进入运行态。

## 代码边界

- `GET /v1/admin/routes` 保留为读取接口。
- 普通路由写入只使用 `POST /v1/admin/routes/transaction` 的 `create/update/delete` 操作；`PUT /v1/admin/routes` 返回 405。
- 入口创建/更新使用 `route_operations`，入口元数据和边操作在同一 SQLite 事务中提交；旧 `routes` 整表字段被拒绝。
- Provider PUT/DELETE 在 SQLite 写锁内读取最新快照，只修改目标 provider 和受影响的失效分支；不再通过内部 provider 列表替换 helper。
- 显式 JSON/TOML 导入仍是带确认的批量恢复边界，不是普通 UI 写入路径。
- 未引入额外 ETag、`expected_version` 或配置版本实体；并发范围由当前 daemon 的 SQLite 写锁限定。

## 非法状态与恢复约束

完整矩阵见[原子配置写入计划](../design/ATOMIC-CONFIG-WRITE-PLAN.md)。本候选重点验证：

1. 环、未知 provider/别名、重复边、批量操作中途找不到目标边时，旧 SQLite、Router、入口索引和 Graph projection 不变。
2. Provider 删除后只移除无法到达任何现存 provider 的分支；有效分支和历史调用记录保留。
3. 入口创建、更新/重命名和删除不留下元数据与路由图半套状态。
4. JSON/TOML 导入在解析、adapter 构造和完整图校验结束前不替换运行快照。
5. 提交后刷新失败不能伪称回滚；持久快照仍是合法权威，返回错误并允许下一次加载重新同步。
