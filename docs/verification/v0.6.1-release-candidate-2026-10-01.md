## 本轮变更

- Android reusable workflow 的四个签名 Secret 改为可选；缺少任一项时，Android job 只输出跳过原因，不阻断桌面、CLI 或 Docker 发布。
- Release 只在 Windows、CLI、Docker 和 Android job 本身成功时发布；Android artifact 仅在 workflow 输出 `apk_available=true` 时下载。
- Windows job 继续以 `if-no-files-found: error` 上传 MSI、NSIS、Portable ZIP 和 Standalone EXE，因此缺少 `jev-switch-standalone-<version>-windows-x64.exe` 会使 Release 失败。

## Secrets 验收边界

本次未配置 Secrets 的工作流已显示 Android 签名跳过，并仍完成 Windows Standalone/Portable、MSI、NSIS、CLI、Docker Release。配置同一专属 keystore 的以下四项后，后续 tag 的 Android job 应完成 `zipalign`、`apksigner verify`，并上传 APK 与 JSON manifest：

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

签名 APK 的 signer SHA-256 应在后续版本保持不变。历史 debug-signed APK 与新稳定签名身份不能直接覆盖安装，首次迁移需要卸载旧 APK。
