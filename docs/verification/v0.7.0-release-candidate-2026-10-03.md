# v0.7.0 候选核验（2026-10-03）

本轮是 minor 功能迭代。与 v0.6.3 的真实 `jev-147` 分开：那次调用已证明 Vercel HTTP 401 后 TypeSafe 官方成功、一个入口记录与两次上游实发；本轮没有再次消耗真实上游额度。发布后应以 Release workflow、资产和真机结果继续补证，不能把本机编译写成设备验收。

## 行为变化

| 范围 | 本轮结果 | 尚需确认 |
|---|---|---|
| 路由账本 | 父请求仍持久化一条；其 `route_trace.attempts` 增加每次 `evaluate` 实测耗时。统计页可切入口/提供商视角；后者按持久 trace 展开 Vercel 失败、TypeSafe 成功等实际外呼，不重复计入口请求。提供商可用性和热力图也使用 attempt 结果。 | 旧历史没有 attempt 的行只按已有数据呈现；费用仍只取选中上游响应。大量旧历史的游标读取与实时 `route_activity` 内存序号边界仍需专项测试。 |
| 路由策略 | 参数化覆盖 HTTP 400/401/402/429/503 在 `on_error=next/fail` 下的继续/停止，保留多跳、重试、坏响应等既有回归。 | sticky、能力跳过、网络超时、在途配置变更等完整组合矩阵仍在计划中。 |

| 演练场 | 轻点/左键切换多选且至少保留一个；右键或 Android 长按独选，菜单键/Shift+F10 为键盘等价操作。 | Android 长按与系统 context menu、批量请求矩阵的设备交互验收。 |

## 人工验收最短路径

1. Windows Standalone：在路由页用三层以上、不同高度的提供商卡片点击“整理布局”，检查节点不重叠、边清楚、拖动后的手动位置仍保留；切统计页用已有 Vercel→TypeSafe 记录核对入口一行、提供商两行及状态/耗时，不发新的真实请求也能验视图。
2. Android：安装同签名 v0.7.0 APK，确认覆盖安装保留配置；演练场轻点 A/B 多选、再长按 B 独选；设置搜索“局域网”应显示并高亮条目，失焦后只取消高亮；LAN 按钮默认熄灭、确认后高亮、再点击关闭。
3. Android 文件/服务：导出设置 JSON 时先检查隐私警示，再到 Downloads 或分享目标打开并确认内容；复制 curl/Token 后到别的输入框粘贴。允许与拒绝通知权限分别启停网关，对照 `/health`、设置页前台服务状态、常驻通知与 tile。Android 7–9 另测日志/JSON 的 FileProvider 分享；没有对应设备就继续标“未实测”。

TUI/Termux、安装器、完整后台生命周期和全链路性能仍不在本次自动核验结论内。
