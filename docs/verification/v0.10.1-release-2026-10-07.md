# v0.10.1 发布核验

日期：2026-10-07
版本：`0.10.1`
范围：provider 服务生命周期、自动探测、公开脚本指南与 Windows Release 门禁

## 交付内容

- Provider 高级配置支持受控服务的启动、停止、状态探查、readiness、超时、启动策略和进程策略。
- Providers 页面按提供商保留服务启停面板展开状态；面板打开时探测服务生命周期状态。每个提供商可以独立关闭 API 自动探测，默认开启。
- 生命周期执行只使用 UI 中登记的通用程序与参数。Laya、StartLux、OneJev 的模型路径、运行时和 qev/llama-server 参数属于外部脚本或私有共享配置，Jev Switch 不注入、不下载、不解释这些模型专用变量。
- 公开指南提供脱敏的 Laya/StartLux 脚本结构、逐项环境变量表、UI 配置步骤、跨平台机制说明和 FAQ；示例不包含机器路径、用户名、模型文件或私有 companion 项目名称。

## 人工核验

维护者在 Windows Standalone 中完成以下本地服务循环：

| 服务 | 验证内容 | 结果 |
|---|---|---|
| Laya | 状态 → 启动 → 就绪/API 探测 → 停止，重复多轮 | 通过；维护者另行确认 UI 中重复启停可用 |
| StartLux | 启动 llama.cpp 与 bridge → readiness → 实际 Jev 请求 → 停止 | 通过 |
| OneJev | 状态 → 启动 → readiness/API 探测 → 停止，连续两轮 | 通过 |

服务脚本失败时，UI 保留生命周期错误码、退出码、请求 ID 和下一步检查方向；“进程启动器仍存在”不会单独被当作 API 已就绪。

## 自动验证

- Rust workspace：`cargo test --manifest-path rs/Cargo.toml --workspace --locked --offline`
- Tauri shell：`cargo test --manifest-path src-tauri/Cargo.toml --locked`
- UI：`npm test --prefix ui`（69 项）、`npm run lint --prefix ui`、`npm run build --prefix ui`
- Laya 运行时配置测试：`python -m pytest scripts/test_laya_runtime_config.py` 等价测试通过
- PowerShell：Laya、StartLux、OneJev 脚本解析通过
- `git diff --check` 通过

## 发布边界

- Windows Release 会上传 MSI、NSIS、Portable ZIP、Standalone EXE、Linux/Windows CLI 和 Docker 镜像；Android 稳定签名 APK 仅在四个仓库 Secrets 齐全时附加。
- Windows 是否使用 Authenticode 由仓库变量 `WINDOWS_SIGNING_REQUIRED` 控制；关闭时随包上传 `windows-signing-status.txt`，不能把未签名包描述成已签名。
- 本版本不宣称演练场已支持多模态信息；该能力已登记到 `ROADMAP.md`，另行设计和验收。
- 云端 provider 没有本地服务启停命令时保持手工管理；平台进程组、Agent 权限范围和跨设备 Android 行为仍以各自证据为准。
