# Kev-0.8B Local Route Verification

Date: 2026-09-28

## Runtime

- Upstream id: `kev08`
- Public model: `kev08-local`
- Base URL: `http://127.0.0.1:8808/v1/systemone`
- Checkpoint: `jaredpalmer/kev-0.8b`
- Base: `Qwen/Qwen3.5-0.8B-Base`
- Backend: official `kev.serve`, Torch CUDA, RTX 2080 Ti
- Serving temperature: `2.3510958125672174`
- FP32 benchmark GPU observation: about `11.4 GiB / 22.5 GiB` with the local stack

The service returns native Choice/Score/Noul decisions and calibrated checkpoint
temperature metadata. It is not a JSON-generation bridge.

## Gateway smoke

The route was registered as a provider plus a service endpoint. A real request
through `http://127.0.0.1:11439/v1/systemone` returned HTTP 200 with:

- `route_trace.selected_provider = "kev08"`
- `route_trace.selected_model = "kev-latest"`
- `upstream_calls = 1`
- fractional upstream `latency_ms` accepted and normalized by the protocol layer

The same request previously returned HTTP 502 before the latency compatibility
fix because Kev reports fractional milliseconds such as `162.4`.

| direct `8808` | 53.75% (43/80) | 152.0 ms | 150.2 ms | not recorded in the original summary | 0 |

## Precision experiment

On this RTX 2080 Ti, BF16 reduced observed GPU memory to about 6 GiB but did
not improve latency: the same life-record run measured 52.5% and 220.5 ms
without CUDA graphs, and 51.25% and 208.5 ms with CUDA graphs. FP32 without
graphs remains the reference serving configuration for quality/latency.

## Prefix-cache warm path

The 80-row life-record benchmark mostly contains distinct states, so it is a
cold-state workload for Kev's prefix cache. A repeated-state smoke sent the same
Choice request ten times:

- direct Kev: first request about `234.5 ms`, later requests `30.4-31.8 ms`;
- Jev Switch: first request about `291 ms`, later requests `46-53 ms`, with
  gateway trace timing about `34-37 ms`;
- all ten choices were identical.

The warm gateway path is in the same latency range as the Laya life-record
baseline (`45.6 ms` mean), while new states remain closer to the `167 ms` Kev
reference. Repeated follow-up questions over one state are therefore a
different workload from first-pass classification of many new states.

An 8-way concurrent repeated-state smoke also completed with zero errors. In
the same local stack, Kev measured about `297 ms` P50 and `342 ms` P95 wall
time, while the comparable Laya run measured about `957 ms` P50 and `1,100 ms`
P95. This is a workload-specific batching/cache observation, not a claim that
Kev is faster for fresh states.
