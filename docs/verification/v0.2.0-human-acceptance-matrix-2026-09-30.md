## User-visible before/after

- Before: a second launch or close can leave the user wondering which process is still alive. After: the shell reports a short, measurable shutdown path and the next launch can prove which daemon it owns.
- Before: the route graph is a static wiring diagram. After: a real request briefly lights the observed edge, with separate success, retry and failure feedback; missing trace data stays unknown.
- Before: the user changes theme manually or accepts the initial system choice only once. After: `system` remains a persistent preference and follows OS changes, while manual modes remain stable.
- Before: OpenRouter is a roadmap sentence. After: the source adapter can be configured, discover `/models`, translate a Jev decision through JSON mode and expose a documented capability boundary; live credentials still decide release readiness.
- Before: visitors must reconstruct the product from the repository. After: GitHub Pages shows the product, real screenshots, quick start, download and limitations in one scan.
