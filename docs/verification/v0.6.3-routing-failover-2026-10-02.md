# v0.6.3 路由 failover 发布核验记录

**目标版本：** `0.6.3`
**基线：**公开 `v0.6.2`
**范围：**多跳路由中 `on_error=next` 的候选切换、候选活动事件和版本门禁。

本次同版本 Android 修复补充了两个平台边界：自定义 keepalive plugin 的权限请求和 Quick Settings toggle 均改由 Rust Tauri command 代理，避免 WebView 直接调用 `plugin:*` 被生产 ACL 拒绝；前台通知服务失败不再回滚已成功绑定的本地 daemon。

## Android HTTP 连通性跟进

维护者在真机确认首页已能启停内置后端，但 WebView 连接 `http://127.0.0.1:11435` 仍报 `Failed to fetch`。本机检查维护者下载的原 `v0.6.3` 签名 APK：AndroidManifest 的 `android:usesCleartextTraffic` 为 `false`（`aapt dump xmltree` 值 `0x0`）。Tauri 生成工程只对 debug 变体开启 HTTP，release 变体默认禁用，因此本机 HTTP API 被 Android 网络策略阻断。访问根路径得到 404 不能说明后端不可用；正确的服务身份探测路径是 `/health`。

同版本修复把 Android release 生成配置的明文 HTTP 显式设为 `true`，并在 CI 打包后检查合并清单；这覆盖内置 `127.0.0.1` 网关和用户主动填写的局域网 HTTP 服务地址。新生成的本地未签名 APK 经 `aapt dump xmltree` 核实该值为 `0xffffffff`（true）。同时增加真实 HTTP Router 回归，检查 Android WebView 的 `http://tauri.localhost` 可读取 `/health` 并通过带 Authorization 的管理请求预检。Rust Android `aarch64` 目标、Kotlin/Gradle release APK 打包与 UI 类型检查、构建及 49 项测试通过；**这不是新版真机连通性证据**。

设置页 Android 调试现提供两路 `/health` 探测：原生 Rust 通过本机 TCP 访问实际监听端口，WebView 通过当前 API 地址执行 `fetch`。若前者成功、后者失败，可进一步定位到 WebView/Android 网络策略或 CORS，而不把“拿到监听句柄”误报为完整可用。私有目录日志可直接在应用内打开全文；Android 10 及以上导出到系统“下载”，Android 7–9 使用系统分享界面。日志默认关闭，仅记录有限的生命周期、监听和探测结果元数据，仍需维护者用新版 APK 验证下载与真机行为。

## 行为修复

- retryable 错误仍按 `RetryPolicy` 在同一候选重试。
- `on_error=next` 在重试耗尽或遇到非 retryable 上游/响应错误后继续下一个候选。
- `on_error=fail` 保持首错返回。
- 最后候选记录 `no_next_candidate`，不会虚构后续调用。
- 多跳入口将候选 provider attempt 与入口父请求关联；本版本仍保留一个持久父请求行，provider attempt 双视图列入后续设计。

## 自动验证

- Rust workspace：`cargo test --manifest-path rs/Cargo.toml --workspace --locked --offline`
- Rust `ts-rs`：`cargo test --manifest-path rs/Cargo.toml --workspace --features ts-rs --locked --offline`
- UI：`npm test --prefix ui`（47 项通过）、`npm run lint --prefix ui`、`npm run build --prefix ui`
- UI 路由活动回归确认 Vercel 分支失败/红色、TypeSafe 分支成功/绿色，共享入口边同时保留两种结果样本。
- UI Android 控制回归确认没有直接调用 `plugin:jev-android-keepalive|...`，网关启停先于通知权限请求，权限失败不会阻止 daemon 控制。
- `cargo fmt --check` 仍受仓库既有未触碰格式差异影响，未将全仓格式化纳入本补丁。

## 真实链路

使用维护者本地已配置的 Vercel 与 TypeSafe 官方提供商，未记录或输出 key：

- 入口：`jev-vercel`
- 请求：`jev-147`
- Vercel 候选：HTTP 401，1 次调用，`next_candidate`
- TypeSafe 官方：`jev-latest` 成功，1 次调用
- 对外结果：HTTP 200，`upstream_calls=2`
- 路由活动：Vercel started/failed、TypeSafe started/succeeded 四个事件
- 监听：验证结束后 daemon 已停止，`11435` 端口释放；Vercel 优先配置保留。

## 验收边界

自动测试和真实链路证明的是后端策略与记录语义。Windows Tauri 原生 WebView/托盘、Android service/tile/通知/生命周期、安装器、TUI/Termux 和完整路由策略矩阵仍需各自的人工或后续专项证据，不能由本记录替代。
