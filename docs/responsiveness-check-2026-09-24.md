# 窗口与响应式布局验收（2026-09-24）

## 要求与取舍

用户反馈 Tauri 首次窗口过大，并要求网关 UI 适配不同像素大小与长宽比，参考 CC Switch。该要求已纳入 [主计划 §3.2](design/ENDPOINT-GATEWAY-ALIGNMENT-PLAN.md#32-后续补充窗口与响应式布局)。最新首窗尺寸证据见文末 2026-09-25 12:28，三屏几何证据见 05:05；早期“仅实测 100%”的记录已被后续增量补充。

[CC Switch 的官方窗口配置](https://github.com/farion1231/cc-switch/blob/main/src-tauri/tauri.conf.json) 在本次查阅时为默认 1000×650、最小 900×600；[其 App 布局](https://github.com/farion1231/cc-switch/blob/main/src/App.tsx) 使用可收缩内容和受限滚动。本项目采用紧凑首窗的方向，同时给 DAG/多入口演练保留不同的布局策略。

- 首窗当前默认 **900×560 逻辑像素**，常规最小值 760×480。此前 1000×650 的实测外框占 1600×852 工作区高度约 81%，按用户反馈收紧；仍按当前显示器工作区和 DPI 计算预算，将边框/标题栏一并限制在工作区的 90% 内，小工作区下最小值也缩小。
- 窗口先隐藏，尺寸和工作区内的位置设置完成后显示。仅首次创建应用窗口时应用此逻辑，后续手动调整/最大化仍由系统管理。
- 页面按 WebView 实际 CSS 视口重排，不以显示器物理分辨率直接选择列数。

```text
屏幕物理尺寸 ── 减去任务栏等 ── 工作区
                                   |
                          DPI换算 + 标题栏预算
                                   |
                          紧凑、居中的首次窗口
                                   |
              +--------------------+--------------------+
              v                    v                    v
         窄：堆叠/换行         矮：内容区滚动        宽：卡片/结果多列
```

## 实现

1. Tauri 的窗口配置与 `window_layout.rs` 负责首窗逻辑像素、物理工作区和边框换算。
2. Shell 将导航/状态与可滚动主体分开，压缩空间时处理登录状态、长 Token ID 与导航关系；Dashboard/Providers 等采用自适应栅格。
3. 演练场在宽度至少 800px 时保持双栏输入；输入有独立滚动和展开状态。在宽度不超过 1100px 或高度不超过 700px 时，所有示例通过下拉框选择，减少示例列表占据的高度。
4. 路由图保留内部平移/缩放/滚动，在窄页面中不拉宽整页；矮窗口降低画布高度，边属性编辑器按宽度变为两列/一列。
5. 入口弹窗以普通容器承接内部滚动，标题与保存/取消区保持在可用视口内。原先直接把滚动放在 `fieldset` 上，在真实浏览器中出现内容越过按钮区，已按截图结果修正。
