## 用户结果

这轮迭代的目标是让 Jev-Switch 更像一个随时可操作的工作台：路由图成为主要画布；常用搜索、启停、比较和统计不再藏在长页面里；测试样例和结果能够保留并再次运行；桌面和移动端都能逐步理解网关正在做什么。

## 已确认决策

- 路由 DAG 是路由页的主工作区，应占据顶栏以下可用窗口；状态、连接提示、缩放、整理布局、表格和选中连线编辑使用浮动 HUD 或可收起的属性面板。
- 演练场状态跨页面切换保留；“高考/2022”等无关命名统一收敛成“数学题”。支持样例导入/导出、多选示例、多个模型入口批量矩阵和重复测试，并以易扫读的矩阵呈现，单项详情和原始 JSON 渐进展开。
- Providers 与 Entries 使用一致的筛选搜索；进入页面时搜索框聚焦，支持键盘快速筛选。Provider 列表可显示基于实际调用记录计算的可用率/频率；数据样本和时间窗口必须显式说明，样本不足时显示未知。
- Provider 自动连通性探测提供用户设置开关，默认开启。关闭后停止后台自动请求；用户仍可手动探测、发现模型或发起真实调用。
- 新增“设置”和“统计”顶栏入口。设置统一承载 APP 全局偏好并可快速搜索；统计集中展示历史调用、趋势和筛选，不让 Dashboard 承担完整报表职责。
- 主题和语言默认跟随系统；用户可在设置中固定 light/dark 或受支持语言。未完成翻译的语言不得注册为可用。
- 桌面 APP 提供网关快速启停操作；“停止”必须调用桌面壳负责的 daemon 生命周期，不能用 local/cloud 鉴权模式代替服务启停。命令面板可导航到设置/统计，并提供真实、可逆的服务动作。
- HTTP 管理 API 总开关与 gateway 调用 API 共用监听服务，但鉴权/路由按既有 API 契约区分；设置必须如实说明关闭管理 API 对 Providers、Entries、统计、设置同步的影响，并保留不会被误锁死的本机恢复路径。
- Provider 可用性时间条只从持久化调用事件/真实探测记录派生；成功率、调用频率、窗口长度和缺失样本不可相互替代。不得将页面打开时一次 probe 描述为历史成功率。
- APP 图标采用彩色但克制、可识别的 Jev/Jev-Switch 品牌表达，并复用同一主资产生成桌面窗口、任务栏、托盘和 Android launcher 图标；已有窗口/托盘标识时，UI 内不重复堆放装饰图标。
- Android 是实验性 Tauri APK，面向没有 Termux 的普通手机用户；首版连接已有云端/局域网 Jev-Switch，不默认在手机上托管 daemon。GitHub CI 构建 APK 不等于 Android 适配或真机验收。

## 实施拆分

| Phase | 范围 | 核心验收 |
|---|---|---|
| 1. 主工作区与低摩擦导航 | Routing 全窗口画布/HUD；Providers/Entries 统一搜索、进入即聚焦；Settings、Stats 导航骨架；主题/语言系统偏好进入设置 | 320×568、390×844、900×560、1600×900 无不合理裁切；键盘焦点可见；路由图可平移、缩放、选择边和编辑属性；设置/统计入口权限正确 |
| 2. Playground 工作台 | 状态持久化；数学题命名；样例导入/导出；多模型 × 多样例矩阵；重复测试批次；历史结果摘要、筛选、逐项详情与原始响应展开 | 刷新/切页/重启后按定义恢复输入和目标；导入校验失败不覆盖现有状态；批量队列有界、可取消、重试不会让旧响应覆盖新轮次；区分单次响应与重复统计 |
| 3. 运行管理与观测 | Provider 自动探测频率开关；真实调用历史统计与 Provider 状态条；独立 Stats 页面；Dashboard/命令面板网关启停 | 关闭自动探测后后台不再调用 probe；统计严格由持久记录聚合并标注窗口/样本；gateway stop 只停止本应用拥有的 daemon，保留配置/数据库并能重新启动 |
| 4. 全局设置与发布边界 | 快速搜索设置项；HTTP 管理 API 开关与本机恢复路径；应用图标统一；Android GitHub CI 实验性 APK | 设置持久化、重启恢复、搜索覆盖全部注册项；API 关闭/恢复有隔离测试；图标多尺寸可读；APK 具备 ABI/version/commit/checksum 元数据并明确 experimental |

每个 Phase 可形成单独 patch Release；如果多个 Phase 同期完成，可合并发版，但不能把未实现项作为 Release 能力发布。

## 数据与安全约束

- Playground 历史如需跨设备或与 Stats/Provider 可用率一致，应使用 daemon 的持久化事件/调用历史；只保存在浏览器 localStorage 的数据要明确标为本机草稿，不声称是服务端历史。
- 示例导入采用有版本的 JSON 结构，验证大小、字段、问题类型和模型目标；导出前不得包含 provider key、admin/caller token 或未经用户选择的历史敏感详情。
- 批量比较会产生真实上游请求和费用。提交前显示“模型数 × 样例数 × 重复次数”的请求上限，使用有界并发，允许取消尚未发出的队列项，并标明取消不保证撤销已到达上游的请求。
- Provider 可用率聚合使用有限窗口和明确分母；direct provider 与 routed endpoint 采用各自稳定身份，不把同地址不同账号合并。
- 服务启停是宿主级副作用，只由 Tauri 壳对自己拥有的 daemon 执行；可复用 UI/API 层返回意图，不向用户数据或运行中的其他 daemon 发 stop 信号。
- 关闭管理 API 不得移除 health/恢复通道，不得使用户无法从本机恢复配置；远程 cloud 部署若关闭管理 API，应说明只剩 gateway 调用能力。
- Android APK 不包含 Windows sidecar；HTTP 明文局域网访问须明确 Android 网络安全策略和风险，默认优先 HTTPS。

## UI 原则（本轮落实）

1. **主动作近手**：画布、搜索、运行和筛选占据主要交互位置，低频/诊断信息进入 HUD、折叠面板或详情。
2. **一眼辨态，展开知因**：状态条、矩阵色阶和趋势图提供扫读；hover/focus/点击可查看样本数、时间窗口、错误和原始数据。
3. **图标表达动作，文字表达结果**：采用 Lucide 语义图标与清晰 tooltip/aria-label；避免 Unicode 箭头和 emoji 充当控件图标，避免重复品牌标识。
4. **统一重复交互**：Provider/Entry 搜索、清空、空结果、键盘导航和焦点行为共用相同模式；二元配置用 toggle，模式选项用 segmented control，数量用 stepper/select。
5. **动效服务反馈**：拖动、排队、成功、失败、重试和停止均反馈实际状态；支持系统减少动效偏好，不用装饰模拟后台活动。
6. **宽高比自适应**：Routing 画布优先使用剩余空间；窄屏时属性面板转为底部/侧边抽屉，表格可滚动，内容不互相遮挡。
7. **可扩展而不造过度框架**：导航、设置项和命令从有语义的注册源派生；具体功能仍由其负责页面/模块拥有，不用一个万能 UI 注册器包住所有业务。
