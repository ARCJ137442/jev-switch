## 执行摘要

**核心问题**: 当前 UI 把「说明书」当成了「控制台」——用户打开界面是为了**看状态、快速操作**，但界面给的是**读文档、理解概念**。

**三大症结**（用户原话 + 代码证据）:
1. **冗余说明文字**：该收进 tooltip 的常驻在界面上（`HomePage.tsx:496` mode hint、`Shell.tsx:191` footer 技术债、`RouteTableForm.tsx:173` debounce 说明）
2. **缺动效与图表**：全站仅 6 处动画（骨架屏 + 脉动），HomePage 四张卡全是 key-value 文字行，没有「一眼看清全局」的视觉形式
3. **该交互的写成字**：mode 切换三步操作 + 弹出文字，listen 编辑点 Edit 才能改，空态显示 TOML 代码块而非引导表单

**深层审美缺陷**:
- **"终端腔"美学与中文冲突**: `font-mono uppercase tracking-widest text-[10px]` 出现 86 次，但中文在等宽字体无字形、uppercase 对 CJK 无效、10px + tracking-widest 撑开字距致不可读
- **页面标题比正文还小**: ProvidersPage 标题 10px，卡片内 provider ID 13px → 层级倒挂
- **Probe 状态丢失**: 健康数据存 `useState`，切页即清空；HomePage 只显示 enabled 灯，无健康信号
- **无日志/历史页**: 四页 `home | providers | routing | playground`，全是配置界面，看不到「过去发生了什么」

---

## 定位判断

**程序本质**: 本地 daemon 的**控制台**（control panel），不是文档站，不是营销页。  
**对标物**: Docker Desktop、Proxyman、LM Studio、ngrok Dashboard —— 都是本地服务控制面板，特征是：
- 状态一目了然（服务跑没跑、流量走哪了、健康不健康）
- 操作就地完成（toggle 开关、inline edit、拖拽）
- 日志/历史可追溯

**当前 UI 错位**: 像一份「如何使用 Jev-Switch」的教学网站，而不是工作台。

- 全站 `animate-` 类仅 **6 处**（`ui/src` grep 统计）

### 3. 交互复杂度
| 操作 | 当前流程 | 理想流程 |
|---|---|---|
| 切换 mode | ① 点按钮 → ② 展开确认条 → ③ 点确认 | toggle 开关直接切 |
| 编辑 listen | ① 点 Edit → ② 输入 → ③ Save/Cancel | inline-edit 点击即改 |
| 查看健康状态 | ① 点 Probe → ② 看结果 → ③ 切页丢失 | 自动轮询 + 持久化 + HomePage 显示 |

- BipartiteCanvas 拖线锚点 **3×3px**（touch target 应 ≥44px）
- 画布强制最小宽 560px + `overflow:hidden` → 375px 手机上右列卡片被裁切
- RouteTableForm 固定列宽，横向溢出无滚动

### 5. 视觉层级倒挂
| 元素 | 字号 | 问题 |
|---|---|---|
| 页面标题（ProvidersPage） | 10px uppercase | 比卡片内容还小 |
| provider ID | 13px | 比标题大 |
| PlaygroundPage hero | 4xl/5xl | 营销式大标题，但页面埋在二级导航 |
| 全站 label | 10px mono uppercase tracking-widest | CJK 字符不可读 |

## 国际化缺陷（CJK Bug）

**问题**: `font-mono uppercase tracking-widest text-[10px]` 样式对中文是**功能性 bug**，不是品味问题：
1. 等宽字体无 CJK 字形 → 浏览器降级到非等宽，标签中英混排视觉断裂
2. `uppercase` 对中文无效（CSS 规范行为）
3. `tracking-widest` 依然生效 → 10px 中文字被硬撑开，间距过大

**证据**: `LangToggle.tsx:15` 显示 "中" 字时，样式声明 `font-mono uppercase tracking-widest text-[10px]`，但 uppercase 对 "中" 不生效，只有 tracking 拉宽间距。

## 功能盲区

### 无日志页
- 路由表：`home | providers | routing | playground`
- **缺失**: 请求历史、failover 记录、cost 统计、upstream 调用日志
- **结果**: 用户看不到「过去 1 小时 Vercel 挂了 3 次自动切到 Laya」这类关键信息

### Probe 状态不持久
- 健康数据存 `ProviderCard` 组件的 `useState` → 切页/刷新即丢
- HomePage 提供商卡片只显示 enabled 灯，无健康状态
- **结果**: 用户无法「一眼看出 laya 是绿的、vercel 是黄的」

### 左列模型来源错误
- `RoutingPage.tsx:245` 左列 `leftIds` 来源：`MODELS_FIXTURE ∪ routes.left`
- `MODELS_FIXTURE = [{ id: 'jev' }, { id: 'local/*' }]`（硬编码 2 个）
- **问题**: HomePage 从 `/v1/models` 拉真实数据，但 RoutingPage 用 mock → 两页数据不一致

## 改进方向（不做具体设计，留给重构阶段）

### 原则
1. **状态可见性优先**: 健康灯、流量图、cost 趋势 → 图形优先，文字补充
2. **渐进披露**: 说明文字收进 tooltip / `?` 气泡 / 折叠区
3. **就地操作**: toggle 直切、inline-edit 点改、拖拽建边
4. **持久化状态**: Probe 轮询 + 存储，HomePage 显示全局健康
5. **日志可追溯**: 新增 Logs 页，显示请求历史 / failover 事件 / upstream 调用

### 技术债清理
- 移除 `font-mono uppercase tracking-widest text-[10px]` 的滥用（86 处）
- 建立清晰字阶：12/14/16/20/24/32，标题 ≥ 正文
- BipartiteCanvas 移动端适配：touch target ≥44px，响应式宽度
- RoutingPage 左列改从 `/v1/models` 拉数据，与 HomePage 对齐

**不是小修小补的问题，而是定位错位**。当前 UI 把控制台做成了说明书。
