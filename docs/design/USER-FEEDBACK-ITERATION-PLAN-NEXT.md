- 桌面主界面已有仪表盘、提供商、入口、路由、演练场、统计、设置七个顶栏页面；维护者已确认当前 Standalone 能启动并到达全部页面。
- 维护者已人工确认便携版/Standalone 冷启动、顶栏与主题、设置内 API 地址/主题/语言/搜索、演练场历史保留与重复测试、路由画布交互等既有路径。窗口关闭会隐藏到托盘；托盘“关窗重启”已人工验证可恢复窗口；选择退出后本地 API 不再响应。
- TUI/Termux 仍标记为“未经人工实测”。维护者报告 Android APK 已安装、演练场和路由初步调用官方 Jev，且新版本机网关启停与 UI 连接正常；这只证明该设备上的这些路径，不证明后台 service、通知、Quick Settings tile、重启/旋转稳定性或其他设备兼容。Android 首次打开直接进入完整 UI 并启动本机网关；用户明确停止后下次保持关闭。
- Playground 的 chip 多选、单模型自动填充、无限重复次数警示、动态 curl、批量矩阵和持久化已在 `v0.5.0` 实现。

## 用户结果

用户打开演练场时，能用同一排样例按钮选择要编辑的输入或组合要比较的样例；批量成本和进度一眼可见。路由图在节点被选择、调用经过、响应成功或失败时都有清楚但不误导的反馈。统计页能回答“哪些入口/提供商近期健康、调用发生在什么时候、我现在筛选的是什么”。Dashboard 则一眼展示服务地址和状态，十分钟流量曲线持续向前滚动。常用操作更容易通过命令面板和状态栏触达。

```text
样例 chip（点击切换多选 / 长按或右键独选） ─┐
模型入口 × 已选样例 × 重复次数 ─────┼─> 可追溯比较矩阵
                                      └─> 摘要优先，单项详情渐进展开

真实调用/探测记录 ─> 日健康矩阵 + 过滤后的历史列表
路由请求/响应事件 ─> 整条线曝光 + 响应辉光 + 最近成败色温
```

### 6. 路由图霓虹式实时反馈

**视觉状态分离：**每条边有“请求曝光”“响应辉光”“近期结果色温”三个独立状态；统计次数不得映射到线宽。

- [x] 收到请求开始事件时，整条线同时曝光变亮，不出现沿一端扫向另一端的动画；请求越密，线体亮度越快趋近上限。
- [x] 尚未返回的请求保持线体热度；响应到达后线体按冷却曲线回落，不能因一个响应立刻熄灭仍有并发请求的边。
- [x] 响应时在线外侧产生一层辉光；成功与失败都可见，约 3 秒逐渐衰减。响应只主要增加辉光，不再把线体加粗。
- [x] 颜色由近期响应成功/失败比例决定，使用最近 5 分钟且最多保留 100 个结果的滑动样本；成功偏绿、失败/超时偏红、混合比例平滑过渡、无样本回中性白。
- [x] 颜色亮度保持固定，只用色相/饱和度表达成败比例和活跃数量；并发时亮度不叠加失控，饱和度与辉光均有上限。
- [x] 动画来自真实请求/响应事件；失败、超时、重试与事件缺失有明确处理。支持 `prefers-reduced-motion`，降低动效时仍保留可辨识的静态状态。

**技术前置：**先确认事件契约是否能区分 request start 与 response completion，并能可靠还原本次调用经过的 DAG 边。若当前记录只有完成事件，不得把同一时刻的完成事件伪装成请求过程；应先补齐事件生命周期或将首版如实限制为响应后效果。

**验收：**合成成功、失败、超时、快速连续、并发与长时间空闲事件，核对整边同时亮、未完成请求保持热度、辉光约 3 秒衰减、色温按滑窗比例变化、无事件回归中性、线宽恒定且颜色亮度不漂移。真实上游联调不是 UI 验收的必要条件。

### 7. Statistics：日历状态矩阵与历史筛选

- [x] 在统计页顶端增加对齐的按日状态矩阵，借鉴参考图的“日格 + hover 详情 + 时间范围切换”阅读方式。
- [x] 提供入口热力图和提供商热力图：纵轴为入口/提供商，横轴为日期；格子颜色表达基于真实请求/探测事件计算的成功率/状态，hover/focus 显示日期、样本数、成功数、失败数和数据来源。
- [x] 无记录显示“无样本/未知”，不可着色为健康；请求结果与连通性探测分别计数，不能将一次自动 probe 当作历史推理成功率。
- [x] 历史调用支持入口、提供商、时间范围、事件类型筛选；保留请求摘要、结构化详情和原始 JSON 的渐进披露。
- [x] 默认每页 50 条；借鉴 CC Switch，允许用户自定义每页条数并用上一页/下一页翻阅。展示页大小不等于后端历史保留上限；按需用游标取旧记录，避免一次渲染无限长列表。
- [x] 检查现有事件读取的 cursor/retention 契约；若单次读取并非完整历史，使用游标继续加载或补一个可分页管理 API，不能只对内存中偶然载入的少量记录宣称全历史筛选。

**验收：**日期单元格在各种宽度下严格对齐；筛选在入口、提供商、日期和事件类型间可组合；50 条默认、自定义条数、上一页/下一页与游标加载均正常；新增 SSE 事件不会打乱筛选或当前页；无样本/加载失败/请求错误分别呈现，不能被画成成功。

- [x] 路由摘要里的“编辑路由”采用与探测耗时一致的次级文本层级；箭头改用 Lucide 图标。

## 数据、交互与工程约束

- 颜色和动效是数据的派生视图，不得取代请求状态、样本数和可访问文本；减少动效时仍要能读懂。
- 历史、热力图、Dashboard 曲线与 DAG 活动效果只使用本地持久记录、明确标注的内存遥测或真实流事件。演练场编辑草稿继续遵守现有本地存储边界，不把本机草稿冒充服务端历史。
- 不把 API key、调用 Token、请求体原文写入命令历史、状态栏、统计矩阵、调试日志或截图。
- 新 UI 字符串同时补 en/zh；其他语言未完成译文前不注册为可选择语言。
- 交互状态需有 loading、empty、error、disabled 与 reduced-motion 表现；多选/独选、F11、命令导航、节点双击均需提供键盘等价入口或语义标签。二值开关采用[固定文案与视觉状态原则](UI-INTERACTION-PRINCIPLES.md)。
- 自动布局与热力图聚合尽量放在纯函数中，避免把图算法、时间窗口与组件副作用混在页面渲染里。
