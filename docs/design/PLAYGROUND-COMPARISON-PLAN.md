## 目标与边界

为同一份 `state` 与 `questions` 同时运行多个模型调用入口，并在一个视图内逐列查看回答、状态、耗时、usage、费用与错误。对比区必须支持两类入口并明确分组/类别，也允许混合比较：

- **对外入口**：Jev Switch 提供给调用方的公开 `model ID`（如 `typesafe-ai/jev`）。请求经过该入口绑定的模型服务配置和路由策略，执行完整入口转换与调用链。model ID 是系统入口标识，不是供应商真实模型名或 `upstream_model`。
- **直接上游入口**：直接绑定一张提供商接入配置卡和一个该账号/资源可用的上游 model，跳过公开入口路由策略，向指定资源做直测。入口仍由 Jev Switch 后端代发，浏览器不得获取或使用上游 key。

`GET /v1/models` 目前只提供对外入口候选；它不能发现/表达直接上游入口。服务端应以复合配置卡为基础：每份提供商接入配置是一张卡，地址相同但账号/key 不同允许各自独立成卡；账号与 key 按卡复用，可用模型列表随该卡绑定资源变化。每张对外入口卡单独配置模型服务及路由策略。直接上游候选必须取自所选提供商卡对应资源的模型清单或可配置 model 值，不能把 provider ID、公开 model ID 或另一个账号的模型混为一谈。

这是对现有单模型演练台的增量能力。契约 06 §2/§5 当前明确是单个 ModelSelect 与 Input/Output 双栏，已有设计目标以保留该调试流程和答案分型为主；横向多入口对比、同一快照批量发起以及列级生命周期属于本次新增需求。应保留既有表单/JSON 编辑、示例、单入口运行、错误解读与计量展示，并将单入口视为多入口能力的合法配置。

## 交互模型

用户编辑一次共享输入，在分组入口栏中选一个或多个对外入口、直接上游入口或二者混合，然后运行。默认建议预置 2 个入口；允许 1 个，也允许继续添加，不把产品规则写成固定 2–4 列上限。横向列数量增长时由比较区承载滚动，窄屏切换纵向卡片流。每个入口提交独立调用并共享同一 state/questions 快照；一个入口失败不阻塞或覆盖其它入口。

运行前冻结请求快照。若用户在请求期间编辑共享输入或入口集合，正在运行的项目继续绑定原快照，界面提示“输入已更改；当前结果属于上次运行”，不悄悄把旧返回结果解释成新输入的结果。可再次运行以生成新一轮；不必清除旧列结果。每个列结果携带 request ID、目标类型与目标身份、提交时间和输入快照摘要，回包只允许写入发起它的 request ID/列实例。

每列显示状态（未运行、等待、运行中、成功、失败、已取消）、自己的运行/取消/重试按钮、端到端耗时、响应答案和计量。顶栏提供运行全部、取消全部。全局并发控制按浏览器发出的请求实施；初版可让用户一次选择任意数量，但采用小型并发池（建议默认 3 个同时在途，队列项可取消）避免大量点击瞬间压垮本机 daemon/上游。已运行项可单独取消，其余队列继续；取消全部同时取消在途和队列项目。取消后重新运行创建新 attempt，迟到的旧回包不得覆盖新 attempt。

结果始终保留调用目标快照和 daemon 返回值两层信息。对外入口显示公开 model ID；直接上游入口显示提供商卡标识与所选上游 model（密钥只显示安全标签，不显示原文）。`response.model` 只作为响应元信息展示，不替代请求目标；如返回值与目标不一致，应同时显示并标记差异，以便排查路由或转换。

## 页面空间与布局

采用“紧凑共享输入区 + 全宽比较区”，避免当前 Playground 页面左侧模型选择卡占掉约三分之一宽度，而单个 TestPanel 又在右侧重复占据宽度。主任务路径从上到下排列，比较结果获得整行宽度；快捷示例放在共享输入标题行/紧邻输入区处，curl 说明继续折叠，不用说明文字填充空白。

## 建议数据模型

```ts
type RunStatus = 'idle' | 'queued' | 'loading' | 'ok' | 'error' | 'cancelled';

interface InputSnapshot {
  stateJson: string;
  questionsJson: string;
  state: JevRequest['state'];
  questions: JevRequest['questions'];
  fingerprint: string; // 对解析后的输入作稳定摘要；用于归属/变化提示，不含 model
}

interface ComparisonAttempt {
  requestId: string;       // 一轮运行 ID
  attemptId: string;       // 单入口重试 ID
  target: ComparisonTarget; // 冻结的调用路径与身份，不含秘密
  snapshot: InputSnapshot;
  status: RunStatus;
  startedAt?: number;
  finishedAt?: number;
  durationMs?: number;     // 客户端测量：排队后发出至响应完成
  response?: JevResponse;
  error?: { message: string; status?: number; upstream?: string | null; retryable?: boolean };
}

type ComparisonTarget =
  | {
      kind: 'public';
      publicModelId: string;
      // 实际使用的入口转换/策略由后端配置解析；请求快照记录可审计的策略版本/标识。
      serviceConfigId?: string;
      routePolicyVersion?: string;
    }
  | {
      kind: 'direct_upstream';
      providerConfigId: string; // 复合提供商卡的稳定 ID，同地址不同账号各有 ID
      upstreamModelId: string;
      // 不含 key、Authorization、完整密钥或可反推出密钥的字段。
    };

interface ComparisonRun {
  requestId: string;
  snapshot: InputSnapshot;
  selectedTargets: ComparisonTarget[];
  attempts: Record<string, ComparisonAttempt>; // 每个稳定 target instance 独立状态/结果
  createdAt: number;
}
```

正在编辑的 drafts 与已提交的 `ComparisonRun.snapshot` 分离。点击运行全部时校验 JSON 和协议输入，解析失败时不发任何请求，并在输入编辑器附近展示错误；成功则建立新 `ComparisonRun`。单列重试复用该轮冻结的 `snapshot` 和完整 `ComparisonTarget`（目标类别、公开 ID 或接入配置 ID + 上游模型），产生新 `attemptId`。如果用户要用更新后的输入执行，点击新一轮“运行全部”即可。

每个 UI 列以稳定的入口选择实例 ID 或本轮 target key 做 key，绝不以数组位置标识回包目标。公开入口以其公开 model ID 区分；直接上游入口至少以 providerConfigId + upstreamModelId 区分，同地址不同账号不可合并。队列的取消删除待发项；在途取消通过 `AbortController` 终止浏览器等待并把列状态落为 cancelled。直接上游接口还需定义后端取消能力；未定义前不得宣称这能撤销已进入上游的计算或费用。

## 答案和计量显示规则

成功结果复用现有 TestPanel 的分型渲染规则：choice/score 展示契约字段和 probability 分布；noul/boolean 展示可用的 `noul` / `probability` 来源及值，**不显示 confidence**。提供可展开原始响应 JSON 以便排查 extra 元数据。

计量区域清楚区分来源：

- `response.usage` 有值：显示真实 usage，包含服务返回的 input/output/reasoning tokens；缺少的字段显示 `—`，不能拿本地估算补齐并伪装成真实值。
- `response.usage` 缺失：可按现有字符数/4 逻辑展示输入 token **估算**，明确“估算”，并说明没有服务端 output usage。估算不可参与真实入口优劣的精确成本结论。
- `response.cost_usd` 是数字时显示服务报告的费用，即使是 0；为 `null` / 缺失时显示“未知”或 `—`，绝不写 `0`。
- 展示响应 `latency_ms`（服务端，若有）与 `durationMs`（客户端本次请求测量）时需标注来源，不能用一个覆盖另一个。顶栏可显示客户端耗时；详情并列显示两者。
- `upstream_calls` 有值时显示实发调用数；缺失时沿用协议既有兼容规则（按 1 解释）并可标记“缺省”。

错误列保留其它列的响应和数据。复用 `SystemOneError` 对 404/422/503 等状态与 upstream/retryable 的现有处理；每列显示可读错误，允许独立重试，不全局清空。

## API 与后端依赖

模型发现须区分两类目标。公开入口从 `GET /v1/models` 发现具体公开 ID；前缀匹配规则（如 `local/*`）不能直接当作具体模型参与比较，需输入符合规则的公开 ID。直接上游入口必须先选择提供商复合配置卡，再从对应资源模型列表选择具体上游 model。若使用内置 fallback，须明确标为未从服务器确认，不能伪装成已发现的可调用入口。

**对外入口**可在初版复用 `postSystemOne({ model: publicModelId, state: snapshot.state, questions: snapshot.questions })`；入口发现继续使用 `GET /v1/models`。每次请求均经过 daemon，符合契约 04 §22。前端需给现有调用增加可选 `AbortSignal` 并传给 fetch；错误映射复用 `SystemOneError`。

**设计起点时，直接上游入口没有可复用的 API；现已按契约 07 实现管理端 provider invoke。** 客户端选择 providerConfigId + upstreamModelId，daemon 从配置取 key 并代发；浏览器不能直连供应商、传递/缓存上游 key，也不能暗中将直测请求改走公开入口路由。具体接口及权限见契约 07，取消浏览器等待不表示上游计算已撤销。复合提供商卡的管理 API/模型发现与对外入口服务及路由配置的改造依赖 [入口与网关对齐计划](ENDPOINT-GATEWAY-ALIGNMENT-PLAN.md)。

契约 01/05 足以支持公开入口的单次请求/响应：`JevRequest.model` 放公开入口 ID，state/questions 保持同一快照。直接上游调用需要显式新契约；不能把 `/v1/systemone` 的 `model` 偷换为 provider ID 或供应商 model。`upstream` 错误字段只作诊断信息。公开入口和直接上游即使选择同一实际供应商模型，语义仍不同：前者运行入口转换及策略，后者绑定具体 provider 配置并绕过公开路由。

当前 HTTP 契约没有服务器端批量原子性、批量限流、任务取消、流式结果或每项独立 trace ID。公开入口对比作为 N 个单请求工作，结果在网络/时间上并非原子一致；并发池只控制本 UI 发出的并发数。直接上游入口则依赖新增的受权限保护后端能力和安全契约，主计划会落实配置/路由数据面；其调用 API 细节实现前再定，不在本文假称已经存在。

## 验收场景

1. 只选一个入口：页面仍可完成原有的编辑、运行、答案分型、错误与计量查看；共享输入区和比较列不出现空白占位内容。
2. 选择两个公开入口并运行：两份 Jev 请求除公开 `model` 外的输入完全一致，结果分别显示在各自公开 model ID 下；每列可独立完成和显示耗时。
3. 两入口先后完成且第二个先返回：回包仍写入正确列；一列 422/503 失败时另一列成功结果保留。
4. 队列中取消一列、运行中取消另一列：前者不发请求，后者显示取消；其它列正常结束；迟到回包不覆盖取消/重试后的 attempt。
5. 仅重试失败列：重试使用相同输入快照和调用目标；成功列保持原结果。输入修改后，新运行使用新 fingerprint；旧回包归属于旧 run 并显示“上次输入”标识。
6. 服务返回 usage 与 cost：按真实数据显示；缺少 usage 时估算项明确标“估算”；`cost_usd: null` 显示未知，`cost_usd: 0` 才显示 0。
7. noul/boolean 答案含 probability 或 noul：显示真实可用字段和值，不出现 confidence；choice/score 继续展示 confidence 与概率分布。
8. `/v1/models` 多入口返回变化：新公开 ID 可被选择；重排不打乱已提交结果列；服务不可达时可识别 fallback 状态。
9. 桌面视口下输入编辑器和两列以上结果能有效使用全宽；窄屏下结果卡纵向排列，JSON/长错误可读且不造成整页横向滚动。
10. 空/非法 JSON、未知或不可用 model ID：本地校验失败不产生请求，服务错误只影响对应列；可修改输入或单独重试。
11. 公开入口与直接上游入口同屏且类别明确：混合运行时前者经过对应服务/策略，后者绑定指定提供商卡和 model 直测；后者绝不偷偷套用公开入口路由。
12. 同一地址配置两个不同账号/key：两份提供商卡独立选择；直测列显示正确卡和该资源对应模型，UI、请求日志和错误体均不泄露 key。
13. 直接上游接口权限缺失或 provider 配置禁用/不存在：后端拒绝该项且不触达供应商，其它公开入口结果照常返回。
14. 输入快照相同、调用目标不同：state/questions 字节/语义一致，只有目标路径差异；回包按稳定目标实例归列，单项重试不修改其它结果。
