## §0 设计原则（一句话）

**Routing 页面是电路板焊接工作台，用户通过拖拽建立可视化的路由连接，对标 Obsidian 白板的可编辑 DAG 图精确度。**

---

## §1 核心隐喻：电路板焊接

把路由配置想象为**可焊接的电路板**：

| 电路板概念 | Jev-Switch 映射 | 交互方式 |
|-----------|----------------|---------|
| **左侧焊点（API 调用点）** | 对外入口卡片的右侧输出端口 | 拖拽起点 |
| **中间节点** | 调用 DAG 的路由/策略节点及输入输出端口 | 建立多跳与分支、编辑属性 |
| **右侧触点（上游出口）** | 提供商复合卡片**左侧**的具体模型端口 | 拖拽终点；绑定接入配置与模型 |
| **电路连线** | 路由箭头（单向流动） | 拖拽连接、重新接线 |
| **线条粗细** | 调用次数统计（对数映射） | 视觉反馈 |

**关键修正**：右侧 provider 卡片的连接点（触点）在**左侧**，不是右侧 — 电流从左到右流动。

## §3 交互细节规范

### 3.1 磁吸机制（Snapping）

**触发距离**: 40px

**视觉反馈（拖拽中）**:
- 箭头终点距离目标端口 < 40px 时：
  - 显示虚线预览箭头（灰色虚线 → 蓝色虚线）
  - 目标端口圆点高亮 + 发光外环（`box-shadow: 0 0 8px var(--accent)`）
  - 虚线箭头末端自动吸附到端口中心

**吸附行为**:
- **不强制中途吸附** — 拖拽过程中不打断鼠标移动
- **松手后吸附** — 鼠标释放时，自动对齐到最近端口

**动效反馈（松手后）**:
- 虚线箭头 → 实线箭头（0.2s ease-out）
- 端口圆点闪烁一次（0.3s）
- 箭头出现淡入动画（opacity 0 → 1，0.15s）

---

### 3.2 拖拽起点（Drag Origin）

**两种模式并存**:

#### 模式 A：从端口小方块拖出（新建连接）
- **触发元素**: 左侧 model 节点右侧的小方块（12×12px）
- **视觉**: 小方块 hover 时变为蓝色，显示 "+" 图标
- **行为**: 点击拖出一条新的虚线箭头
- **用途**: 创建新路由

#### 模式 B：从箭头左半部分抓取（重新连接）
- **触发元素**: 已有箭头的左半部分（起点到中点区域）
- **视觉**: hover 时箭头起点显示小圆点（6px），光标变为 `grab`
- **行为**: 拖动时原箭头消失，显示虚线预览，松手后更新路由
- **用途**: 修改已有路由的源 model

---

### 3.3 端口可视化（Port Visualization）

**位置**: provider 卡片**左侧边缘**（修正：不是右侧）

**样式**:

| 端口类型 | 视觉 | 说明 |
|---------|------|------|
| **Pin 端口** | 实心圆点，蓝色（`var(--accent)`），6px | 钉死端点（如 `laya-english`） |
| **Pass 端口** | 空心圆点，灰色边框，6px | 透传端点（如 `* input model`） |

**交互状态**:
- **Normal**: 圆点 6px
- **Hover**: 圆点放大到 8px + 高亮
- **Drag Nearby（< 40px）**: 圆点放大到 10px + 蓝色发光外环
- **Connected**: 圆点颜色加深，内部显示连接数（如果 > 1 条）

**布局**:
```
┌─────────────────────────────────────┐
│ ◉ laya-english (pin)      4 routes │  ← 实心圆点在左侧边缘
│ ◉ laya-multilingual                │
│ ○ * input model (pass)             │  ← 空心圆点
└─────────────────────────────────────┘
```

---

### 3.4 拖拽终点反馈（Drop Target Feedback）

**靠近端口（< 40px）时的视觉反馈**:

1. **端口圆点放大**: 6px → 10px（0.15s ease-out）
2. **发光外环**: `box-shadow: 0 0 12px var(--accent)`
3. **虚线箭头吸附**: 箭头末端对齐到端口中心
4. **端口行高亮**（可选）: 端口所在行背景变为 `var(--surface-hover)`

**松手后（成功连接）**:
- 圆点恢复 6px（或 8px，如果有多条连接）
- 箭头从虚线变为实线（0.2s）
- 端口闪烁一次（0.3s）

---

### 3.5 删除交互（Delete Interaction）

**三种方式（按用户习惯选择）**:

#### 方式 1: Inspector 面板删除按钮
- 点击箭头线条 → 右侧弹出 EdgeInspector 浮层
- 面板底部显示红色 "Delete" 按钮
- 点击按钮 → 删除路由

#### 方式 2: 键盘 Delete / Backspace
- 点击箭头选中（箭头高亮为蓝色）
- 按 Delete 或 Backspace 键 → 直接删除
- 无二次确认（可撤销）

#### 方式 3: 右键菜单
- 右键点击箭头线条
- 弹出上下文菜单：
  ```
  ┌──────────────────┐
  │ Edit Route       │
  │ Duplicate (Ctrl+D) │
  ├──────────────────┤
  │ Delete (Delete)  │  ← 红色文字
  └──────────────────┘
  ```

**删除动画**:
- 箭头淡出（opacity 1 → 0，0.2s）
- 同时箭头收缩到中点消失（scale 1 → 0，0.2s）

---

### 3.6 箭头重连（Re-routing）

**交互流程**:

1. **抓取起点**: 鼠标 hover 到箭头左半部分，光标变为 `grab`
2. **开始拖动**: 按下鼠标，原箭头消失，显示虚线预览
3. **拖动中**: 虚线箭头跟随鼠标，靠近端口时触发磁吸反馈
4. **松手确认**: 释放鼠标，虚线变实线，路由更新到新的源 model
5. **取消操作**: 拖动中按 Esc 键 → 恢复原箭头，取消重连

**视觉状态**:
- **原箭头**: 拖动时消失（opacity 0）
- **虚线预览**: 灰色虚线（normal）→ 蓝色虚线（靠近端口）
- **目标端口**: 高亮 + 发光

---

### 3.7 箭头样式（Arrow Styling）

#### 基础样式
- **线条宽度**: 由调用次数决定（见 §3.8）
- **颜色**: 
  - 正常: `var(--border-strong)` 灰色
  - hover: `var(--accent)` 蓝色
  - error: `var(--danger)` 红色
  - selected: `var(--accent)` 蓝色 + 加粗
- **虚实线**:
  - 实线: 默认
  - 虚线: `on_error=next`（failover 链）

#### 箭头中点标签
- **priority 数字**: 显示在箭头中点（小圆圈内）
- 小圆圈的颜色用一个类圆环图来表示（边缘是带颜色圆环）反映路由在24h的API调用成败情况（红失败绿成功黄慢速（>1s）），数字在小圆圈内
  ```
  ──────●10──────>
  ```
- **hover 浮动卡片**: 鼠标 hover 箭头时，显示浮动标签卡片
  ```
  ┌─────────────────────┐
  │ Priority: 10        │
  │ Sticky: session     │
  │ On Error: next      │
  │ Calls (24h): 1,234  │  ← 调用次数
  └─────────────────────┘
  ```

### 3.8 调用次数可视化（Call Count Visualization）

#### 数据源
- **后端**: 存储调用统计数据（每条路由的调用次数）
- **推送**: 通过 SSE 推送实时更新（类似 Dashboard 的事件流）
- **前端**: 接收 SSE 事件，更新箭头粗细

#### 线条粗细映射（对数映射）

| 调用次数 | 线条宽度 | 计算公式 |
|---------|---------|---------|
| 0 次 | 2px | 基准 |
| 1-9 次 | 2px | `2px` |
| 10-99 次 | 4px | `2 + 2 * floor(log10(count))` |
| 100-999 次 | 6px | `2 + 2 * floor(log10(count))` |
| 1000+ 次 | 8px | `2 + 2 * floor(log10(count))` |

【批注：粗一些，避免点不到】

**计算函数**:
```typescript
function getStrokeWidth(callCount: number): number {
  if (callCount === 0) return 1;
  return Math.min(2 + 2 * Math.floor(Math.log10(callCount)), 8);
}
```

#### 统计时间窗口
- **窗口**: 最近 24 小时（滑动窗口）
- **刷新频率**: 读取历史调用记录（这部分也存入数据库，后续可以配置数据保留期限（默认先存最近一个月的）），SSE 推送，前端实时更新（< 5s 延迟）
- **显示**: hover 浮动卡片显示精确数字（如 "1,234 calls"）

#### 视觉效果
- 高频路由：粗线条（4px）+ 深蓝色
- 低频路由：细线条（1px）+ 浅灰色
- 零调用：虚线（1px）+ 更浅的灰色

### 3.9 多边错开（Multiple Edges Offset）

**场景**: 同一端口连接多条箭头

**策略**: **放射状扩散**（用户反馈）

**实现**:
- 3 条箭头：-15°, 0°, +15°
- 5 条箭头：-30°, -15°, 0°, +15°, +30°
- 计算公式:
  ```typescript
  const count = edges.length;
  const angleSpan = 30; // 总角度跨度（度）
  const angles = Array.from({ length: count }, (_, i) => {
    const offset = (i - (count - 1) / 2) * (angleSpan / (count - 1 || 1));
    return offset;
  });
  ```

**视觉效果**:
```
      ╱  ← +15°
     ─   ← 0°
    ╲    ← -15°
[port]
```

### 3.10 键盘快捷键（Keyboard Shortcuts）

| 快捷键 | 功能 | 说明 |
|-------|------|------|
| **Delete / Backspace** | 删除选中的箭头 | 选中后按键直接删除，无二次确认 |
| **Esc** | 取消当前操作 | 拖拽中按 Esc → 取消拖拽，恢复原状 |
| **Ctrl+Z** | 撤销 | 撤销上一次操作（新建/删除/修改路由） |
| **Ctrl+Shift+Z** | 重做 | 重做上一次撤销的操作 |
| **Ctrl+A** | 全选 | 选中所有箭头 |
| **Ctrl+D** | 复制 | 复制选中的箭头（创建一条同样的路由） |
| **Shift+Click** | 多选 | Shift 点击切换选中状态（可叠加选择） |

**撤销栈**:
- 支持最多 50 次撤销
- 撤销操作类型: 新建边 / 删除边 / 修改边属性 / 批量删除
- 栈结构:
  ```typescript
  interface UndoAction {
    type: 'create' | 'delete' | 'update';
    route: Route;  // 路由快照
  }
  const undoStack: UndoAction[] = [];
  const redoStack: UndoAction[] = [];
  ```

## §5 服务入口配置（未来亮点功能）

### 5.1 设计动机

**问题**: 同一个 model 有多条路由时，后端的行为是什么？

**答案**: 可配置的路由策略 — **这是 Jev-Switch 的亮点功能**

### 5.2 路由策略

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| **Failover**（默认） | 按 priority 顺序尝试，第一条成功即返回；失败后根据 `on_error` 决定是否尝试下一条 | 高可用场景（Vercel 挂了切 Laya） |
| **Race** | 同时发送给所有路由，取最快响应 | 低延迟场景（多上游竞速） |
| **Load Balancing** | 按 priority 权重随机选择一条路由 | 负载均衡场景（分散流量） |
| **Shadow** | 主路由返回结果，同时向影子路由发送请求（不等待响应） | A/B 测试场景（对比上游） |

### 5.3 配置示例

**配置文件扩展** (`providers.toml`):
```toml
[models.jev]
strategy = "failover"  # 默认策略
# strategy = "race"    # 竞速模式
# strategy = "load_balance"  # 负载均衡
# strategy = "shadow"  # 影子模式，shadow_target = "laya"
```

**UI 配置**:
- Routing 页面左侧 model 节点右键菜单 → "Configure Strategy"
- 弹出模态框，选择策略 + 配置参数

## §9 开发注意事项

### 9.1 SVG 性能优化

**场景**: < 50 条边，无需虚拟化

**优化点**:
- 使用 `<path>` 而非 `<polyline>`（更少的 DOM 节点）
- 箭头 marker 定义在 `<defs>` 中复用
- hover 状态用 CSS `:hover`，不用 React state（避免重渲染）

### 9.2 拖拽实现

**库选择**: 不使用重型库（如 react-dnd），手动实现 `pointerdown/pointermove/pointerup`

**原因**:
- 需要精确控制磁吸逻辑
- 需要自定义预览线（虚线箭头）
- 性能更好（无额外抽象层）

### 9.3 撤销栈

**存储**: 不存储完整路由表，只存储差异（delta）

**示例**:
```typescript
// 新建边
{ type: 'create', route: { left: 'jev', right: 'vercel', ... } }

// 删除边
{ type: 'delete', route: { left: 'jev', right: 'vercel', ... } }

// 修改边
{ type: 'update', before: { ... }, after: { ... } }
```

### 9.4 SSE 连接管理

**重连策略**: 指数退避（1s, 2s, 4s, 8s, max 30s）

**心跳**: 每 30s 发送 `ping` 事件，超时未响应则重连
