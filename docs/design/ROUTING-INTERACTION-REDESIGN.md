# Routing 页面交互优化方案

**日期**: 2026-09-24

> **历史提案说明（2026-09-27）：**本文是早期截图驱动的交互提案，部分设想和当前实现/契约可能不一致，不可直接视为已实现功能。后续路由交互设计以 [路由交互规范 v2](ROUTING-INTERACTION-SPEC-v2.md) 为准，当前实施和验收边界以[入口网关认知对齐与实施计划](ENDPOINT-GATEWAY-ALIGNMENT-PLAN.md) 为准。

## 核心设计隐喻：单向流动的电路板

把路由配置想象为**可焊接的电路板**：

| 电路板概念 | Jev-Switch 映射 | 交互方式 |
|-----------|----------------|---------|
| **焊点（API 调用点）** | 左侧输入模型端口（如 `jev`, `laya-english`） | 拖拽起点 |
| **中间路由点** | 可选的中间节点（DAG 编辑体验） | 可添加、连接、删除 |
| **末端出口点** | 右侧上游提供商内部模型（如 `laya-english` pin） | 拖拽终点 |
| **电路连线** | 路由箭头（单向流动） | 拖拽连接、重新接线 |

**关键隐喻**：用户就像在电路板上"焊接线路"，从左边的 API 入口接线到右边的上游出口。

---

## 当前问题

基于 Image #2 的现状分析：

1. **箭头两端不可拖拽** — 用户无法通过拖拽重新安排路由
2. **箭头末端未对齐上游模型** — 箭头指向 provider 卡片整体，而非内部的具体模型端口（`laya-english` pin）
3. **缺少中间路由点** — 无法实现"先路由到 A，失败后再路由到 B"的多级路由

---

## 优化方案 1：可拖拽的箭头端点

### 交互设计

**起点（左侧 model 端口）**：
- 用户点击 `model` 标签旁的小方块（端口），拖出一条新箭头
- 或者抓住已有箭头的起点，重新拖到另一个 model

**终点（右侧 provider 内部 model 端口）**：
- 用户把箭头末端拖到右侧 provider 卡片内的具体 model（如 `laya-english` pin）
- 箭头吸附到该 model 的端口（视觉反馈：高亮、磁吸效果）

### 实现要点

| 元素 | 当前实现 | 优化后 |
|------|---------|--------|
| 左侧 model 端口 | `model` 标签旁的小方块，不可拖拽 | 可拖拽起点，支持新建箭头 |
| 右侧 provider 内部 model | `laya-english` pin，无端口可视化 | 显示端口（小圆点），可作为箭头终点 |
| 箭头 | SVG path，固定连接 | 可拖拽两端，实时更新路径 |
| 吸附逻辑 | 无 | 拖拽到端口附近时磁吸（距离 < 20px） |

## 优化方案 2：箭头末端对齐上游模型端口

### 当前问题

Image #2 中，箭头指向 provider 卡片的边缘（如 `laya` 卡片右侧），而非具体的模型端口（如 `laya-english` pin）。

### 优化方案

**右侧 provider 卡片内部模型端口可视化**：

```
┌─────────────────────┐
│ ● laya       4 ep   │  ← provider 名称
├─────────────────────┤
│ ◉ laya-english pin  │  ← 端口（箭头终点）
│ ◉ laya-multilingual │
│ ◉ laya-router       │
│ ○ * input model pass│  ← passthrough 端口
└─────────────────────┘
```

**端口样式**：
- `pin` 模式：实心圆点 `◉`（蓝色），表示"钉死"到该模型
- `pass` 模式：空心圆点 `○`（灰色），表示"透传"模型名

**箭头连接规则**：
- 箭头末端必须连接到右侧的某个 `◉` 或 `○` 端口
- 一个端口可以接收多条箭头（多个左侧 model 路由到同一个上游 model）

## 优化方案 3：中间路由点（DAG 编辑体验）

### 设计目标

支持多级路由：`jev` → 中间路由点 A（failover 逻辑）→ `laya-english` 或 `vercel/typesafe-ai/jev`

### 交互设计

**添加中间路由点**：
- 点击画布空白区域，或点击"+ Add routing node"按钮
- 出现一个浮动的"路由节点"卡片（类似 Obsidian Canvas 的节点）

**中间路由点卡片**：
```
┌────────────────┐
│ Failover Node  │  ← 节点名称（可编辑）
├────────────────┤
│ on_error: next │  ← failover 策略
│ priority: 0    │
│ sticky: none   │
└────────────────┘
  ↑ 入口端口
  ↓ 出口端口（可多个）
```

**连接规则**：
- 左侧 model → 中间节点 → 右侧 provider model
- 中间节点可以有多个出口（如 `on_error: next` 时，失败后尝试下一个）

### 实现要点

| 特性 | 实现方式 |
|------|---------|
| 节点拖动 | 监听 mousedown/mousemove/mouseup，更新 SVG transform |
| 节点连接 | 从节点出口端口拖出箭头，连接到另一个节点或右侧 provider |
| failover 逻辑 | 中间节点的 `on_error` 属性决定箭头走向（next/fail/retry） |
| 持久化 | 扩展路由配置格式，支持中间节点（`routes` 数组中新增 `type: "node"`） |

## 用户文档：电路板焊接隐喻

**写入目标**：`docs/user-journeys/ROUTING-GUIDE.md`

### 标题：把 Jev-Switch 路由想象为可焊接的电路板

**左边的焊点（API 调用点）**：
- 你的客户端调用 `POST /v1/systemone`，model 字段填 `jev` 或 `laya-english`
- 这些 model 就是电路板左边的"输入焊点"

**右边的焊点（上游出口点）**：
- 你配置的 provider（如 `laya`, `vercel`）内部的每个模型（如 `laya-english`, `typesafe-ai/jev`）
- 这些模型就是电路板右边的"输出焊点"

**电路连线（路由箭头）**：
- 你通过拖拽把左边的焊点接线到右边的焊点
- 电流单向流动：客户端请求 → Jev-Switch 路由 → 上游 provider

**中间路由点（可选）**：
- 如果你需要 failover 逻辑（"先试 A，失败后试 B"），可以在中间加一个"路由节点"
- 就像电路板上的分流器或开关

## 实施优先级

| 优化项 | 优先级 | 预计时间 | 依赖 |
|-------|-------|---------|------|
| 箭头末端对齐上游模型端口 | P0（视觉修正） | 1 小时 | 修改 SVG path 计算逻辑 |
| 可拖拽的箭头端点 | P1（核心交互） | 2-3 小时 | 实现拖拽监听 + 吸附逻辑 |
| 中间路由点（DAG 编辑） | P2（高级功能） | 4-6 小时 | 扩展路由配置格式 + 节点 UI |

**建议顺序**：P0 → P1 → P2（先修正视觉问题，再实现交互，最后扩展高级功能）
