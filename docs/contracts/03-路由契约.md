# 契约 03 · 模型路由 DAG

> **作者**：Mimo-V2.6-Pro · 2026-09-23 · 状态：**定稿**  
> **正名**：**模型路由 DAG**（准确、可拓展）；**二部图 = 其中最简单的形式**，仅作默认查看/编辑视图。

## 1. 语义模型

```text
节点 N = 对外 model id ∪ 可选中间别名 ∪ 提供商/上游
边   E = 有向 (from, to, match, priority, sticky, on_error, upstream_model?)
```

- **不同模型 → 自动路由**：`exact` / `prefix` 命中 `from` 上的出边
- **相同模型 → 可切换**：同一 `from` 多条出边，按 `priority` 有序候选
- **可多跳**：`from` 可以是另一节点 id（别名链）。**引擎从第一天按 DAG 写**，禁止 core 写死「只有左右两列」

### 二部图退化

最简实例是两层：`对外 model id ∥ 提供商`，单跳边 —— 即二部图连线题。  
UI 第一版用该形式验证交互；**不是**路由模型本身。

## 2. 序列化（与图形界面双向等价）

```toml
# 别名/中间节点（可选；最简形式可省略）
[[routes]]
left  = "jev"
match = "exact"
right = "jev-fast"            # 允许指向别名节点，形成多跳
priority = 5
on_error = "next"

[[routes]]
left  = "jev"
match = "exact"
right = "vercel"
upstream_model = "typesafe-ai/jev"
priority = 10
sticky = "session"
on_error = "next"

[[routes]]
left  = "jev"
match = "exact"
right = "laya"
upstream_model = "laya-english"
priority = 30

[[routes]]
left  = "local/*"
match = "prefix"
right = "laya"
priority = 40
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `left` | string | 边起点：对外 id / 别名 / 前缀 |
| `match` | `exact` \| `prefix` | 默认 `exact` |
| `right` | string | 边终点：provider id **或** 下游节点 id |
| `upstream_model` | string? | 发给上游前的 model 改写；空 = 沿用 |
| `priority` | int | 同 `left` 下越小越优先 |
| `sticky` | `none` \| `session` | 默认 `none` |
| `on_error` | `next` \| `fail` | 默认 `next` |

**兼容**：旧式 `[router] "m" = "upstream"` = 单条 `match=exact` 边。

**扩展预留**：字段名不禁止日后加 `from`/`to` 别名；**不**把节点拆成「只许 model / 只许 provider」两张表。

## 3. 选路 API

```rust
pub struct RouteCtx {
    pub sticky_key: Option<String>,
    pub exclude: BTreeSet<UpstreamId>,
}

pub struct Candidate {
    pub upstream_id: UpstreamId,
    pub upstream_model: String,
    pub priority: i32,
    pub hops: Vec<NodeId>,      // 审计用路径
}

impl Router {
    pub fn select(&self, model: &str, ctx: &RouteCtx) -> Result<Vec<Candidate>, RouterError>;
}
```

- 返回**有序候选**，不是单个 Upstream
- `select` 只认识 id + Capabilities + priority；**不认识** HTTP / URL / 字段方言
- 顶层按候选 try-next；`upstream_calls` 累加

## 4. 行为规则

| 场景 | 行为 |
|---|---|
| 无匹配边 | 404 `UnknownModel` |
| 候选全部失败 | 按最后错误映射状态码 |
| `on_error=next` | 429/5xx/Timeout/Network 试下一候选 |
| `on_error=fail` | 第一次错误即返回 |
| capability 不匹配 | 该候选跳过（不计入失败重试语义） |
| `sticky=session` | 同 `sticky_key` 粘住上次成功候选；失败再 failover |
| 多跳环 | **加载配置时拒绝**（DAG 约束） |

## 5. 与 sub2api 对照

| sub2api | 本契约 |
|---|---|
| `CompositeModelRoute.public_model` | `left` |
| `match_type` | `match` |
| `target_platform` | `right`（provider 侧） |
| `upstream_model` | `upstream_model` |
| `priority` | `priority` |
| `SelectAccountForModel*` + excludedIDs | `select` + `RouteCtx.exclude` |

## 6. 实践条款（UI 形态）

- 默认编辑器 = **二部图连线题**（左 = 对外 id，右 = 提供商）
- 连线浮层可编辑 `priority` / `upstream_model` / `sticky` / `on_error`
- 真实场景跑通后书面记录：**保留二部图最简视图** 或 **升级通用 DAG 视图**
- 无论视图如何，**`[[routes]]` 数据模型不变**
