# 契约 07 · 入口网关修订（2026-09-24）

状态：实施中。来源：[用户确认的入口网关计划](../design/ENDPOINT-GATEWAY-ALIGNMENT-PLAN.md)。本修订更新旧契约的配置归属和 UI 形态，保留 Jev 协议、适配器边界与密钥防泄漏不变量。具体完成证据记录到实施验收，不以本文替代测试。

本文的存储、迁移与 API 细节是实施者依据用户目标作出的工程方案，并非用户在弹窗中逐项选择的答案；用户已确认的产品决定以来源计划 D01–D12 为准。

## 接入配置与持久化

Provider ID 标识一份接入配置，不以 URL 去重。`kind` 选择适配器类型，`id` 可以由用户命名；多个同 kind、同地址、不同凭据的配置均可注册。对外读取仍只返回 `api_key_masked/api_key_set`，新增 `models` 记录该配置的模型集合，可选 `name/account` 用于展示。写入密钥保持旧有省略/null 保留、空字符串清除的约定。

SQLite 统一快照作为提供商、入口和路由的运行配置权威来源。首次从旧 TOML 导入，已有入口策略与 enabled 状态应保留；后续更新在数据库事务中提交成功，再替换可读的内存快照。数据库位置按配置实例隔离。TOML 的兼容导入/导出及外部修改检测必须明确呈现，不能静默忽略用户的手改。迁移失败不得以空配置覆盖既有数据。

兼容导入的完成记录使用独立 `data_migrations` 命名表，不能与 schema 版本号共用编号。旧预发布数据库曾将入口导入和 Token schema 同时记为 v3：升级按实际表/列补齐 Token schema，并将旧入口导入标记保留为已执行，避免复活用户删除的入口。首次根入口导入与完成标记在同一 savepoint 内提交；已有非空入口集合及独立策略不被覆盖。

## 对外入口 API

沿用 `/v1/admin/endpoints`、`/v1/admin/endpoints/{id}` 和 `/v1/admin/config/default_strategy`。DTO 由 Rust `ts-rs` 导出，前端只导入生成类型。

- POST：`{ id, strategy_config, routes? }`，原子创建入口及给定路由；未给路由时创建可编辑空入口，不虚报可调用。
- PUT：`{ id?, strategy_config?, enabled?, routes? }`；省略 routes 保持不变，提供数组则原子替换该入口出边。重命名同步其路由引用；冲突返回 409，不留下部分更新。
- DELETE：删除对外入口与关联路由，实际调用不能继续命中旧入口。若中间节点因此失去全部出边，继续清理指向它的悬空分支，保留其他有效分支。中间别名不是服务入口，不能通过此 API 删除。
- GET：状态、路由数及统计来自真实配置/请求记录；未知健康不能计作健康。
- 未知入口 404；禁用入口不得继续执行；下一请求使用已成功提交的配置；重启保持一致。

`strategy_config` 沿用判别联合：`follow_global`、`failover`、`race { timeout_ms }`、`load_balance { weight_mode }`、`shadow { shadow_target }`。全局默认不得设置为 follow_global。策略参数与合法候选在写入时校验；各策略的请求级行为与计量必须实测。调用 token 不覆盖同一入口路由。

多跳候选遵守契约 03 的逐层顺序：同一 left 下 priority 数值越小越优先，先展开更优根分支的下级候选。不能只取末边 priority 再全局排序，否则根分支优先级会失效。管理端始终读取完整持久图，包括停用入口出边；公开调用仅允许已发布且启用的入口，中间别名不是隐式公开服务。

入口创建、更新/重命名、整表路由保存及 TOML 显式导入统一校验最终完整图：节点标识非空、无环，right 必须引用接入配置或仍有 exact 出边的别名。入口更新在同一事务内校验，拒绝后元数据、路由和运行态保持原值。删除仍被路由引用的提供商配置会被拒绝；应先修改引用路由。停用提供商可以保留配置引用，执行时另行检查启用状态。

全局默认 API 的 `default_strategy` 为字符串：兼容 `failover/race/load_balance` 简单名称，也支持 JSON 编码的上述策略对象，并原样回读参数。竞速超时范围为 1–300000ms；负载均衡 `weight_mode` 为 `equal`（均权）或 `priority`（较小 priority 获得更高权重）；影子目标不能为空。前端以参数表单呈现，不要求产品用户手写内部 JSON。

## 计量与调用记录

`upstream_calls` 记录实际进入适配器执行的候选数量，不直接使用预先计划的候选总数。Race 获胜后中止尚未完成的其他 future；这不保证上游已经执行的计算或费用被撤销。Shadow 在确认后台调用进入执行后运行主调用，影子完成不阻塞主结果返回。

`JevResponse.usage/cost_usd/latency_ms` 对应返回的上游结果，其余候选/影子调用的 usage 和费用当前没有汇总。`route_trace` 明示此范围，并提供 daemon 测量的 `gateway_latency_ms`。前端分别显示客户端、网关、上游耗时；多个上游调用时不能把返回结果费用当作整个策略的账单。

请求事件与个人持久调用记录包含上游调用次数、usage 和费用。统计耗时使用网关 wall clock；存在未知费用或尚未汇总的多次上游调用时，`total_cost` 返回 null。个人历史和个人 SSE 统一来自持久 `call_logs`，共享数据库 ID、detail 与 `since` 游标，刷新/重连可以去重并在重启后续读。管理端全局事件列表及其 SSE 来自容量 200 的内存 EventBus，使用独立游标空间，不能与个人调用游标混用，也不是完整持久审计历史。

删除入口不删除已有调用历史。历史 `endpoint_id` 不以外键级联依赖当前入口行，Token 统计与个人历史在删除后及重启后仍可读取；已被接纳的在途调用完成后仍归属于受理时的入口标识。历史迁移保留全部字段、事件 ID 和自增序列高水位，不能让客户端的 `since` 游标因升级失效。现有入口重命名会同步历史入口标签，此次未改为另一套不可变业务 ID。

## 运行身份

公开 `/health` 保留 `status/version` 并增加 `product: "jev-switch"`、`api_revision: 1`、`build_revision: string | null`。修订号表示本轮入口网关 API 契约，构建修订在 CI 中来自实际提交；未提供时保持 null。

Web UI 核验服务身份和接口修订；Tauri 复用已有 daemon 时还核对版本与壳一致。仅 HTTP 200、旧二键健康响应或未知服务不能当作新版应用已经启动的证据。发行包仅加载随包内核/静态资源，开发路径回退只在 debug 构建启用。

## 直接上游演练 API

`POST /v1/admin/providers/{id}/invoke`，沿用管理认证与本地访问限制。

- 请求是标准 `JevRequest`；其中 `model` 是指定接入配置下的具体上游模型，state/questions 语义不变。
- daemon 解析配置 ID、检查存在/启用/能力与输入，再使用该配置的地址与凭据调用；不经过对外入口路由，不接受浏览器携带新的地址或上游 key。
- 返回标准 `JevResponse`。错误使用统一 `ErrorBody` 并脱敏；未知配置 404、禁用配置拒绝调用、管理认证失败 401/403，均不得触达上游。
- 浏览器可取消等待；除非后端取消确实传播并有验证，不宣称已撤销上游计算或费用。
- `/v1/models` 仍表示对外候选。上游候选来自接入配置的 models，手动填写具体模型必须明确其来源，不能假称已发现。

## 界面与验收

Routing 增加对外“入口”配置 tab，卡片与编辑器使用上述真实 API。图形从左侧对外入口，经中间 DAG 节点，连到右侧提供商复合卡片内的模型端口；拖线、属性编辑和表格操作共享同一配置文档。环路、重复/失效引用、保存失败必须有反馈，撤销恢复完整属性。

Playground 支持对外/直接上游/混合比较，冻结输入与目标身份；独立运行、取消、重试，迟到响应不得污染新 attempt。中文/英文及可扩展语言选择同等适用。新增用户流程最终以真实后端端到端操作验收。
